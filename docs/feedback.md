# 内测反馈

首页、“我的”和采集进度页右下角均有“意见反馈”入口。访客无需登录，只需填写反馈内容，不要求选择类型或填写联系方式。后台统一归类为“其他反馈”，联系方式为空。自动附带仅页面路径、构建版本和服务器时间，不读取投资计划、本地记录、查询参数或浏览历史。

## 后台查看

打开 https://supabase.com/dashboard/project/vxwthnmoroyxqnloonqi/editor ，选择 `public` schema 下的 `feedback` 表。建议按 `created_at` 降序排序。直接编辑 `status` 为“待处理”“处理中”或“已解决”。`category`、`content`、`contact`、`page_path`、`version` 分别是类型、内容、选填联系方式、页面和版本。

## 权限和容量

- 公开客户端只拥有 提交字段（含 id）的列级插入权限，没有读取、修改或删除权限。状态、时间由服务器默认设置。
- RLS 开启，无访客读取策略；只有管理员或服务端 service_role 能读取和处理反馈。
- 私有 schema 中的限流触发器串行核对全站最近一小时和 24 小时提交数，分别最多 100/1000 条。它不通过公开 RPC 暴露，不授予访客执行权限，也不存储 IP。
- 内容最多 2000 字，联系方式最多 120 字。浏览器提交成功后有 60 秒冷却；这只是操作体验限制，数据库全局限流才是服务端容量保护。当前未接入人机验证，后续可按真实垃圾反馈量调整。
- 重试使用相同 UUID，网络结果不确定时避免重复入库；返回最小响应，不返回反馈内容。

## 验证

`npm test` 覆盖传输字段白名单、验证、网络失败、重复重试和权限/限流失败；`tests/database_feedback.sql` 以事务回滚检查匿名提交、匿名/登录访客无法读取、禁止伪造状态、空内容、修改和删除权限，以及服务端小时限额。

已用本地页面真实提交一条自动化测试反馈，确认云端所有字段正确后清理了该测试记录。前端使用构建时从 package.json 读取的版本号。
